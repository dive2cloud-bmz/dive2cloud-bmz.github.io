Agent 记忆系列（08）· 遗忘与巩固：为什么「永不遗忘」的 Agent 是糟糕设计

本篇是「Agent 记忆系列」第 8 篇。前面 7 篇我们一直在解决「怎么记住」——存储、写入、检索、评估。今天我们反过来问一个反直觉的问题：什么时候应该主动忘掉？ 一个把所有东西都记住、永不删除的 Agent，看起来很强大，实际上会越来越慢、越来越蠢、越来越危险。遗忘不是记忆系统的 bug，而是它的核心 feature。

🚀 核心洞察：无限增长的记忆库，等于没有索引的日志表

作为 PostgreSQL 后端工程师，我们对「无限增长的表」有本能的警惕。一张只写不删、没有分区、没有归档策略的日志表，会带来什么？

  • 索引越来越大，B-Tree 越来越深，查询越来越慢。
  • 表膨胀（bloat）严重，VACUUM 追不上写入。
  • 冷热数据混在一起，热点查询被大量冷数据拖累。
  • 磁盘迟早写满，某天凌晨把整个实例拖垮。

Agent 记忆系统面对的是同一个问题，只是换了张皮。如果每一轮对话、每一个观察、每一条中间推理都被永久写入向量库，你会得到：

  • 检索精度下降：候选集里塞满了三个月前早已过时的信息，Top-K 召回的相关性被稀释。
  • 矛盾与陈旧：用户上周说「我搬到上海了」，但库里还留着半年前「我在北京」的记忆，检索时两条都命中，Agent 精神分裂。
  • 成本爆炸：向量库规模线性增长，存储、索引重建、检索延迟全部跟着涨。
  • 隐私风险：本该在会话结束后清除的敏感信息，永久留存，成了合规隐患。

所以，好的记忆系统一定同时是一个「好的遗忘系统」。人脑就是最好的证明：我们记不住上周三午饭吃了什么，但记得住三年前换工作的决定——遗忘是为了给重要的事情腾出信噪比。

🧠 核心概念

1. 遗忘的三种机制：TTL、衰减、容量淘汰

遗忘不是「随便删」，而是有策略的资源管理。工程上主要有三种机制，可以组合使用。

机制 触发方式 PG 类比 适用场景
TTL 过期 到达固定生存时间即失效 Redis EXPIRE / 分区表按时间 DROP PARTITION 工作记忆、会话上下文、临时缓存
时间衰减 相关性随时间指数下降，不硬删 排序时对 age 做惩罚权重 长期记忆的软性降权
容量淘汰 库满时按策略驱逐 LRU/LFU 缓存淘汰 固定预算的短期记忆缓冲区

TTL 过期最简单直接：写入时打一个 expire_at 时间戳，检索时过滤掉、后台定期物理清除。工作记忆天然适合 TTL——一次任务完成，中间的临时观察就没必要留了。

时间衰减更柔和，它不删除记忆，而是在检索打分时给旧记忆打折。经典公式是指数衰减：

λ 是衰减率。λ 越大，遗忘越快。这对应人脑的「遗忘曲线」——艾宾浩斯早在 1885 年就发现记忆强度随时间指数下降。

容量淘汰用于固定大小的缓冲区，比如「只保留最近 20 轮对话的工作记忆」。满了就淘汰。LRU（最近最少使用）淘汰最久没被访问的，LFU（最不经常使用）淘汰访问次数最少的——和数据库缓冲池的淘汰算法一模一样。

2. 巩固：从短期记忆到长期记忆的「转正」

遗忘只是硬币的一面，另一面是巩固（Consolidation）——把值得长期保留的信息，从易失的短期记忆「提炼、压缩、转正」到持久的长期记忆。

这直接对应神经科学里的「记忆巩固」：人在睡眠时，海马体（短期）会把白天的经历重放，重要的部分固化到大脑皮层（长期）。Agent 的巩固过程几乎是同构的：

巩固的核心动作有三个：

  • 摘要压缩：把 50 轮啰嗦对话压成 5 条关键事实。省 token，也省检索噪声。
  • 事实抽取：从自然语言里抽出结构化三元组，如 (用户, 居住地, 上海)，存进知识图谱或事实表。
  • 冲突消解：新事实和旧事实矛盾时（北京 → 上海），要么更新覆盖，要么保留时间线（valid_from / valid_to）。

这里有个关键设计选择：巩固应该异步做。就像 PG 的 CHECKPOINT 不会卡在用户事务的关键路径上，巩固任务也应该在后台批处理，不能拖慢 Agent 的实时响应。

3. 更新与冲突消解：记忆不是 append-only

新手最容易犯的错，是把记忆库当成 append-only 的日志——只加不改。但真实世界的信息会变：用户改了偏好、换了工作、更新了目标。如果只追加不更新，记忆库很快就充满自相矛盾的「历史化石」。

三种冲突消解策略：

策略 做法 PG 类比 代价
覆盖更新 新事实直接替换旧值 UPDATE ... SET 丢失历史，无法追溯
时间线版本 旧记录标记失效，新记录带 valid_from 双时态表 / SCD Type 2 存储更大，查询更复杂
软性降权 不删旧的，靠时间衰减自然沉底 排序惩罚 短期内仍可能命中旧值

生产系统里，对「事实型记忆」（居住地、偏好）推荐时间线版本，既能回答「现在住哪」也能回答「以前住哪」；对「体验型记忆」（闲聊）用软性降权就够了。

4. 什么绝对不能忘：记忆的分级保护

遗忘要有边界。有些记忆是「高压线」，无论多旧都不能自动淘汰：

  • 用户显式要求记住的（”记住我对花生过敏”）——这类是安全/健康红线。
  • 系统级约束与偏好（”永远用中文回复”）——影响所有后续交互。
  • 合规要求保留的审计记录——受法律法规约束。

工程上给每条记忆打一个 pinned 或 priority 标记，遗忘策略跳过高优先级项。这就像数据库里有些配置表，无论如何清理日志都绝对不能碰。

🔗 后端桥接：用 PostgreSQL 的数据生命周期理解记忆遗忘

这一整篇的概念，几乎都能在 PG 的数据生命周期管理里找到镜像。

Agent 记忆概念 PostgreSQL 对应 共同的本质
TTL 过期 分区表 DROP PARTITION / pg_cron 定时清理 按时间批量淘汰冷数据
时间衰减打分 查询里 ORDER BY relevance / age 让新数据排序占优
容量淘汰（LRU/LFU） shared_buffers 缓冲池淘汰 固定预算下的驱逐
巩固（摘要转正） 物化视图 / ETL 汇总到数仓 明细压缩为聚合
冲突消解-时间线 双时态表 / SCD Type 2 valid_from / valid_to
后台异步巩固 CHECKPOINT / autovacuum 不阻塞前台事务
表膨胀清理 VACUUM / pg_repack 回收无效数据空间
pinned 高优先级 配置表 / 约束不可删 关键数据的保护

一个特别贴切的类比：巩固 ≈ autovacuum + 物化视图。 autovacuum 在后台默默回收死元组、更新统计信息，让查询计划保持锐利；物化视图把明细汇总成可快速查询的聚合。记忆巩固做的是同一件事——后台默默把原始对话「回收+汇总」成精炼事实，让检索保持又快又准。你不会想关掉 autovacuum，同理，你也不该让 Agent「永不巩固」。

下面是一个可运行的最小实现，演示 TTL 过期、时间衰减打分、容量淘汰和后台巩固四件事。用标准库即可运行，无需外部依赖。

运行结果解读

  • 查居住地时，只返回「上海」——旧的「北京」被 update_fact 标记 valid_until，检索时被过滤，但历史仍在库里可追溯。
  • 查过敏时，「花生过敏」因为 pinned=True 拿到 10 倍加权，无论多旧都稳稳排在前面，且永远不会被 TTL 或容量淘汰清除。
  • 如果持续写入超过 capacity=5 条，_evict_if_needed 会用 LFU 淘汰访问最少的非 pinned 项——和数据库缓冲池同一套逻辑。

这个 60 行的小玩具，已经把生产级记忆系统的四大遗忘/巩固机制跑通了。真实系统只是把 _match 换成向量检索、把 consolidate 里的拼接换成 LLM 摘要而已。

📰 技术雷达

Mem0 的自动记忆更新。 Mem0 的一大卖点就是内置了「ADD / UPDATE / DELETE」的记忆操作决策——它用 LLM 判断新信息是该新增、更新还是删除旧记忆，本质上就是自动化的冲突消解。这正是本篇「更新与冲突消解」的产品化。

Letta（原 MemGPT）的记忆分层与驱逐。 MemGPT 把有限的上下文窗口类比成操作系统的「主存」，把外部存储类比成「磁盘」，用分页（paging）机制在两者间换入换出。当主存满了，它会把不常用的记忆「换出」到外部——这就是操作系统级的记忆淘汰思想。

遗忘曲线与间隔重复的复兴。 一些研究开始把认知科学的间隔重复（spaced repetition）引入 Agent 记忆：被反复检索到的记忆强化、加长 TTL；长期无人问津的记忆自然衰减。让记忆强度随「使用频率」动态变化，而不是简单的时间线性淘汰。

GDPR 与「被遗忘权」的工程化。 合规角度，「被遗忘权（right to be forgotten）」要求系统能彻底删除某用户的全部记忆。这对向量库是个真实挑战——如何保证一条记忆从索引、副本、缓存里被干净抹除，正在成为记忆基础设施的必答题。

小结

这一篇我们把记忆系统「反过来」看了一遍：

  • 遗忘是 feature 不是 bug：无限增长的记忆库 = 没有归档策略的日志表，迟早拖垮精度、成本和合规。
  • 三种遗忘机制：TTL 过期、时间衰减、容量淘汰，分别对应 PG 的分区清理、排序惩罚、缓冲池驱逐。
  • 巩固 ≈ autovacuum + 物化视图：后台异步把原始对话压缩成精炼事实，让检索保持又快又准。
  • 冲突消解：记忆不是 append-only，用时间线版本（SCD Type 2）既能答「现在」也能答「过去」。
  • 分级保护：pinned 高压线记忆（过敏、系统偏好、审计）无论多旧都不淘汰。
