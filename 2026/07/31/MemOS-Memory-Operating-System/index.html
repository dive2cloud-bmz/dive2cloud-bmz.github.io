MemOS：面向 AI 系统的记忆操作系统

什么是 MemOS

MemOS（Memory Operating System）是由上海交通大学、浙江大学等团队联合研发的开源 AI 记忆操作系统，2025 年 7 月首次发布，当前版本为 MemOS 2.0 “Stardust”。它的核心主张是：像传统操作系统管理 CPU、内存和存储一样，将 LLM 的记忆作为一种可调度、可治理、可演进的系统资源来管理。

与仅做”存取”的记忆工具不同，MemOS 提供了一套完整的记忆生命周期管理体系——从记忆的生成、激活、合并到归档和过期，覆盖了 Agent 记忆的全生命周期。项目以 Apache 2.0 协议开源，在 LoCoMo 基准上取得 88.83 分，LongMemEval 89.20 分，BEAM-10M 56.75 分，在多跳推理和时序推理维度上大幅超越 mem0、LangMem、Zep 和 OpenAI Memory。

设计哲学

MemOS 将传统操作系统的概念映射到记忆管理领域：

传统 OS 概念 MemOS 对应
进程调度器 MemScheduler（记忆调度器）
文件系统 MemVault（记忆仓库）
系统调用 Memory API（记忆接口）
内存管理 MemLifecycle（生命周期管理）
权限控制 MemGovernance（治理层）

其设计理念建立在三个支柱之上：记忆即系统资源（Memory as System Resource）、演进即核心能力（Evolution as Core Capability）、治理即安全基础（Governance as Foundation for Safety）。

三类记忆

MemOS 统一管理三种根本不同的记忆形态：

文本记忆（Plaintext Memory）。 显式的、可动态检索的知识模块——可编辑、可追溯、可存储。在内部组织为层次化图结构，按”任务→概念→事实”路径管理。这是最贴近人类”我知道什么”的部分。

激活记忆（Activation Memory）。 推理过程中的中间状态，以 KV-Cache 为核心结构，辅以隐藏状态和注意力权重。支持懒加载和选择性冻结，让 Agent 在多轮对话中高效复用计算状态。MemOS 的 KV-Cache 注入可将首 token 延迟降低高达 91%。

参数记忆（Parameter Memory）。 编码在模型权重中的知识和能力，通过 LoRA/Adapter 等方式作为可加载的”能力模块”动态挂载。这让一个基础模型可以在运行时按需获得特定领域的能力，而无需全量微调。

三类记忆之间支持跨类型转换：文本记忆可编译为 KV-Cache 加速注入（Plaintext → Activation），频繁使用的文本知识可蒸馏为参数模块（Plaintext → Parameter），模型内在知识可外化为可审计的文本（Parameter → Plaintext）。这些转换由策略感知调度（Policy-Aware Scheduling）统一管理。

MemCube：统一记忆封装

MemCube 是 MemOS 的最小可调度记忆单元，由两部分组成：

记忆载荷（Memory Payload）： 实际内容——文本、图像、工具调用痕迹、人格设定等。

元数据头（Metadata Header）： 三类属性——

  • 描述性标识：时间戳、来源签名、语义类型
  • 治理属性：访问控制、生命周期策略、优先级、合规追溯
  • 行为使用指标：访问模式、上下文指纹、版本链

MemCube 的设计使记忆变得”可调度、可共享、可组合”——多个 MemCube 可以组合为 Multi-Cube（复合知识库视图），支持跨 Agent、跨平台的记忆迁移和共享。

三层系统架构

接口层（Interface Layer）。

  • MemReader：将自然语言请求解析为结构化的 MemoryCall
  • Memory API：提供 Provenance（溯源）、Update（更新）、LogQuery（日志查询）等标准接口
  • Memory Pipeline：可链式编排的记忆处理管线（检索 → 增强 → 更新 → 归档），支持 DSL 定义

运行层（Operation Layer）。

  • MemOperator：执行标签化、知识图谱构建、语义分层、路径解析等操作
  • MemScheduler：类型感知的记忆调度器，决定”何时使用哪类记忆、以何种形态”，支持异步处理，声称毫秒级延迟
  • MemLifecycle：管理记忆的五个生命周期状态——Generated（生成）→ Activated（激活）→ Merged（合并）→ Archived（归档）→ Expired（过期）

基础设施层（Infrastructure Layer）。

  • MemGovernance：策略引擎，执行隐私、合规和使用规则
  • MemVault：持久化存储抽象
  • MemLoader/MemDumper：跨平台的记忆导入导出
  • MemStore：发布-订阅机制的记忆共享总线

核心能力模块

Tree Text Memory（树形文本记忆）。 文本记忆不是扁平列表，而是按 Topic → Concept → Fact 的三级树形结构组织。越靠近根节点的内容越稳定、越抽象；叶子节点是具体事实，变更频率最高。这种结构让检索可以从粗到细逐层展开，也让”巩固”操作有了清晰的语义——把碎片 Fact 向上聚合为 Concept 摘要。

Dream Module（梦境巩固模块）。 模仿人类睡眠记忆巩固的离线处理机制。五种触发动机：新颖性（Newness）、频率（Frequency）、冲突（Conflict）、反馈（Feedback）、碎片化（Fragmentation）。四种操作：Create（新建）、Update（修订）、Merge（合并）、Archive（归档）。每条记忆维护 DreamMemoryLifecycle 状态：last_hit_at、hit_count、usefulness_score、invalidated_by_feedback、status。Dream 在后台定期运行，将碎片化的短期记忆整合为长期稳定记忆。

MemFeedback（记忆反馈修正）。 允许用户或上层系统通过自然语言对已有记忆进行修正——“这条不对，实际情况是……”。系统使用 LLM 判断修正的合理性，自动标记旧记忆为”被反馈失效”，并生成修正后的新记忆版本。

Skill Memory（技能自演进）。 从 Agent 的操作轨迹中自动提取可复用的程序性知识，分四个层级递进：L1（原始操作痕迹）→ L2（策略提取）→ L3（世界模型）→ Skill（可直接调用的结晶化技能）。让 Agent 在使用过程中自动积累和改进自己的操作方法论。

Multi-Cube（复合知识库）。 将多个 MemCube 组合为一个逻辑视图，支持跨领域、跨 Agent 的知识组合。例如一个客服 Agent 可以同时加载”产品知识 Cube”和”客户历史 Cube”，在保持各自独立治理的同时实现联合检索。

基准测试表现

基准 MemOS 得分 说明
LoCoMo 88.83 多轮对话记忆基准，所有类别第一
LongMemEval 89.20 长期记忆评估，含知识更新维度
BEAM-10M 56.75 1000 万 token 超长记忆基准（ICLR 2026）
PersonaMem v2 40.58 人格一致性记忆
HaluMem 80.91 记忆幻觉检测

在 LoCoMo 上”所有类别均排名第一，尤其在多跳推理和时序推理维度上有巨大优势”，超越 mem0、LangMem、Zep 和 OpenAI Memory 等主流方案。时序推理相较 OpenAI Memory 提升 159%。

部署方式

MemOS 提供四种接入路径：

  1. 云 API（托管服务）： 获取 API Key 直接调用，免运维
  2. 自托管 Docker： git clone + docker compose up，依赖 Neo4j（图数据库）+ Qdrant（向量数据库），API 服务于 localhost:8000
  3. OpenClaw 云插件： openclaw plugins install，对接 MemOS Cloud
  4. 本地插件（memos-local-plugin 2.0）： 100% 本地运行，使用 SQLite 存储，支持 FTS5 + 向量混合检索、智能去重、分级技能演进

适用场景

MemOS 最擅长的场景包括：需要跨会话长期记忆的 Agent 系统、多 Agent 协作（记忆共享与隔离）、需要记忆可审计和可治理的企业级应用、个人助手型产品（偏好积累、习惯学习）、以及需要在多模型/多平台间迁移记忆的场景。

局限性

无本体治理。 MemOS 的知识图谱没有 RDF/OWL 级别的 schema 定义和约束验证，实体类型和关系类型由数据自然生长，缺乏形式化治理手段。

部署复杂度。 完整部署需要 Neo4j + Qdrant + LLM 服务 + 应用服务四个组件，相比单一 Postgres 方案运维成本更高。

写入路径复杂。 记忆写入存在多条路径（add/feedback/dream/reorganize），各路径对同一记忆的修改可能产生竞态，需要仔细设计一致性策略。

无原生双时序。 虽然 MemCube 有时间戳和版本链元数据，但不具备 Graphiti/Zep 那样的事件时间 + 系统时间双时序建模能力，无法做”某个历史时刻的认知是什么”这样的时间旅行查询。

社区与成熟度。 2025 年 7 月首发，相对年轻。虽然论文基准成绩优秀，但大规模生产环境的验证案例尚不充分。

与其他方案的定位对比

  • 对比 mem0：MemOS 提供完整的生命周期管理、多类型记忆和调度能力，mem0 更轻量但功能单一（latest-wins 覆写、无图谱）
  • 对比 LangMem：MemOS 有独立的 Dream 巩固和 Feedback 修正机制，LangMem 依赖 LLM 三路判决（INSERT/UPDATE/DELETE）
  • 对比 Cognee：MemOS 上层能力更丰富（Skill、Dream、Feedback），Cognee 有本体治理和 ECL 管线
  • 对比 GBrain：MemOS 是运行时系统（API 驱动），GBrain 是文件系统（Markdown-in-Git）

小结

MemOS 代表了 AI 记忆系统从”存储工具”向”操作系统”演进的方向。它不仅回答”记住什么”，还回答”何时用、以何种形态用、用完后怎么维护、如何安全治理”。三类记忆的统一管理（尤其是 KV-Cache 和 LoRA 层面的激活/参数记忆）是其独特之处——大多数竞品仅处理文本层面的记忆。Dream 巩固 + MemFeedback 修正的组合让记忆具备了”自我进化”的能力，而 MemCube 封装则为多租户、多 Agent 场景下的记忆隔离和共享提供了干净的抽象。
